# Orchestrator

Coordinate work using the project's chosen source and execution policy. Resolve [workflow selection](../workflow-setup/references/workflow-selection.md), read only that mode's guide, and refresh current work records, dependencies, owners, branches, PRs, and meaningful watcher state.

Select unblocked ready delivery items. Parent outcomes aggregate work; unresolved decision records need discovery or triage. Reuse an existing owner and lane rather than dispatching the same item twice. In repository mode, reconcile current shared and active branch records before claims or state changes.

Use the available delegation mechanism only within its actual authority. A request to coordinate work does not override restrictions on creating separate user-visible tasks, subagents, external messages, or recurring automations. If delegation is unavailable, prepare a concrete handoff or coordinate existing owners without inventing a new lane.

For an authorized dispatch, name one delivery owner, the source item, exact base, scope, acceptance proof, and genuine external gates. Use `worktree-isolation` for a new isolated lane. Apply the project's risk policy without turning ordinary uncertainty into a new planning or approval cycle.

Expect an executable result and proof through the real changed seam. Keep in-scope defects with the delivery owner. Use `reconcile-project` when state conflicts or a decision depends on freshness, not to replay unchanged history.

Activate the project's required independent review when a concrete immutable head and evidence exist. A focused pre-edit review is useful only for a named dangerous boundary. Reviewers supply evidence; they do not grant edit or shipping authority.

For each material finding, decide whether to fix before merge, accept within delegated risk authority, create a concrete follow-up, or ask the user about a genuine unresolved decision. A further review needs a named evidence gap.

With delegated shipping authority, decide only after acceptance proof, current head/checks, findings, and external gates support the outcome. Record the decision in the authoritative work item. Follow the selected mode's completion/publication rules; reconcile an accepted or merged result before marking its shared record complete.

Use a single owner for a PR's next poll. Recurring monitoring requires the user's request and the actual automation tool's authorization. Reuse an existing watcher and stop it at its declared condition.

Finish with truthful work state, one owner and next action per active item, and explicit evidence or authority gaps. Do not implement product code or merge merely because this skill is active.

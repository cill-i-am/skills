# How-to guide: accomplish a task

Start from the reader's real goal, not a tour of product controls. Assume the
stated prerequisite knowledge; supply what this particular task requires.

## Writing shape

- Use a specific task or symptom as the title and state the intended result.
- Identify starting conditions, required permissions, and relevant constraints.
- Give the necessary actions in a useful order. Where paths differ, state the
  condition for choosing each path instead of silently assuming one environment.
- Put cost, data-loss, security, or irreversible-action warnings before the step.
- Provide a success check and relevant recovery or escalation guidance. State
  limits where recovery is unavailable or unverified.

A how-to can contain branching decisions; it need not be a single linear recipe.
Keep background short and link to explanation. Link to reference for exhaustive
options instead of embedding an option catalogue in the procedure.

## Troubleshooting

Organize around the observed symptom, safe diagnostic checks, what the results
mean, the matching remedy, and how to verify recovery. Distinguish a possible
cause from a confirmed diagnosis. Put an exhaustive error-code list in reference.

Illustrative title: **Retry a failed import**. Derive actual steps from the target
product rather than this example.
